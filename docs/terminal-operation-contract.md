# Terminal operation contract

This table answers the eight transaction/replay questions from the architecture refactor handoff (section 13) for the terminal surface handled by `ServerActor`: `createOrAttach`, `write`, `resize`, `terminal.read`, `setOutputPaused`, `detach`, `terminate`, `terminal.create`, `terminal.attach`, `terminal.restart`, `terminal.reclaim`, `terminal.driver.list`, `terminal.runningProcesses`, and `terminal.pulse.*`. Companion to `orchestration-operation-contract.md`, `project-operation-contract.md`, `workspace-operation-contract.md`, and `tab-layout-operation-contract.md`; update the table and its pinning tests together.

Authority splits three ways, and the split is the point of this document:

- Persisted workspace and tab records live in `RuntimeStore`. A `kind = "terminal"` tab row owns the public session handle through `payload.terminalSessionId` and carries `spawnOnCreate`, `terminalPulse`, and launch metadata; the row survives host restarts.
- Terminal history lives in `TerminalHostHistoryStore`: one `checkpoints` row per session plus sequenced `outputChunks` rows. It is the only scrollback that survives a host restart.
- Live PTY state lives in `ServerActor.sessions` and nowhere else: PTY handles, the bounded input queue (64 writes), the scrollback ring, attached client ids, per-client delivery cursors, current dims, the `SessionDriver` seat, and the session instance id are all in memory. A `sessionId` absent from `sessions` fails `require_session` with `Terminal session is not attached: {id}`; a session-scoped request never rebuilds the map from persisted state. Only `createOrAttach`, `terminal.attach`, and `terminal.restart` mint or remint a PTY.

View and attachment state is per client and ephemeral: `output_paused_clients`, `output_resync_pending_clients`, and `delivered_output_cursors` live on the session, and `dispose_client` detaches a disconnected client from every session without touching the PTY.

Every operation runs on the actor mailbox. `write` and `terminal.pulse.configure` enter through the deferred-request path (`deferred_requests.rs`), and the runtime-mutation barrier rejects `createOrAttach`, `write`, `terminate`, `terminal.create`, `terminal.attach`, `terminal.restart`, and `terminal.pulse.configure` while a mutation is outstanding; `terminal.read`, `resize`, `setOutputPaused`, `detach`, `terminal.reclaim`, `terminal.driver.list`, `terminal.runningProcesses`, and `terminal.pulse.status` stay available. `HostError::State` messages go to the wire verbatim (clients pattern-match some of them), `HostError::Format` lands as `FormatException: ...`, and `HostError::Conflict` adds `errorCode`/`errorDetails`. Mobile clients are restricted to an allowlist: `terminal.create`, `terminal.attach`, `terminal.restart`, `terminal.driver.list`, `write`, `resize`, `setOutputPaused`, `detach`, and `terminate`.

## Attach, create, and restart

| Operation | Instance check | Replay | Same id + different payload | Commit vs publish | Lost reply retry | Restart recovery | Stale owner / wrong actor |
|---|---|---|---|---|---|---|---|
| `createOrAttach` | `sessionId`, `workspaceId`, `tabId`, `workingDirectory` are required strings; `launch` is only parsed on the spawn path; a running session in `sessions` attaches by handle alone | Attaching a running session returns `created: false` with the scrollback snapshot and seats the client's delivery cursor at the stream end | The live PTY wins: the attach path never compares `workspaceId`/`tabId`/`launch` against the session, so stale metadata cannot respawn or retarget it | On the spawn path `Session::start` writes the initial checkpoint before the session enters the map; the reply then carries `snapshotBase64` (tail capped at `restore_snapshot_bytes`), `snapshotCols`/`snapshotRows`, `driver`, `running`, `exitCode` | Re-running returns the same session with `created: false`; on a dead or absent handle it remints the same session id instead of minting a new one | Host restart empties `sessions`; the next attach remints the handle from `checkpoints` + `outputChunks` through `take_terminal_restart_state` | Attaching a human client (mobile, or a local `app` role) to an `automationOwned` tab marks the run taken over; an automation CLI attach is deliberately not a takeover |
| `terminal.create` (mobile) | `workspaceId` must name an existing workspace | Not idempotent: every call mints a fresh tab id and session id | n/a (ids are server-minted) | Tab row upserts first, then `create_or_attach`; on failure the tab row is removed before the error is returned, and `workspaceTabsChanged` only broadcasts on success | A lost reply produces a second tab; there is no client op id | Mobile tabs do not set `spawnOnCreate`, so the reconciler leaves them alone and the PTY appears on the next attach | Claims the mobile driver seat when the request states both `cols` and `rows`; an absent or half-stated viewport changes nothing |
| `terminal.attach` (mobile) | `tabId` must be a terminal tab whose workspace exists; the session id resolves payload `sessionId`, then `payload.terminalSessionId`, then the tab id | Idempotent through `create_or_attach`; a live session returns `created: false` | Live PTY wins, same as `createOrAttach` | No new store writes on the live path; response is `{tab, attachment}` | Safe; reattaches the same session | Remints the session from its checkpoint when the PTY is gone | Claims the mobile driver seat; `automationOwned` takeover applies through `create_or_attach` |
| `terminal.restart` | All of `sessionId`/`workspaceId`/`tabId`/`workingDirectory`/`launch` required; a live session under that id must store the same `workspace_id` and `tab_id` or the call fails `Terminal restart metadata does not match the live session.` | Not deduplicated: every accepted call kills the current PTY and spawns a new one under the same handle with a fresh instance id, and always reports `created: true` | The live session's stored metadata is authoritative; a mismatch fails closed before anything is killed | Exit push, orchestration cleanup, output flush, and the durable-write barrier run before the old session leaves the map; the new `Session::start` checkpoints before insert; the requester attaches and every other attached client is `attach_for_resync`'d (paused, cursor dropped) and gets an `outputResyncRequired` event on a timer | Safe but heavy: it spawns yet another PTY; the interim one is terminated with history preserved | Same `take_terminal_restart_state` machinery: in-memory scrollback of the dead session first, then the persisted checkpoint buffer, then empty; the absolute stream position carries over | The metadata match is the wrong-workspace fence; instance/generation guards drop startup input, deferred Enter, and pulse writes aimed at the pre-restart session |

## Input and viewport

| Operation | Instance check | Replay | Same id + different payload | Commit vs publish | Lost reply retry | Restart recovery | Stale owner / wrong actor |
|---|---|---|---|---|---|---|---|
| `write` | `require_session`; `dataBase64` must decode | No dedupe; every accepted write queues the bytes again | n/a | The request parks until the PTY writer thread reports `InputWritten`; that completion is what publishes `ok` or the write error. `deferredEnter` keeps the trailing Enter adjacent to its payload in one queue item, and `bracketedPaste` wraps the bytes before enqueue | A lost reply duplicates the input on retry | Queued input dies with the PTY; nothing persists it | Exited session: `Terminal session is not running.`; writer gone (the Windows post-exit drain window): `terminal input writer is unavailable`; full queue: `terminal_input_backpressure: terminal input queue is full`, the prefix the host itself matches to retry orchestration Enter and pulse writes. An empty non-`deferredEnter` write is an immediate `ok` no-op. A successful mobile write claims the driver seat |
| `resize` | `require_session` | Last write wins; re-applying the same dims is a no-op | n/a | A mobile resize claims the driver seat and applies the phone's dims in place; a desktop resize while the phone drives is recorded as `desktop_dims` and applied on reclaim; otherwise `session.resize` applies immediately. `terminalDriverChanged` only broadcasts on a change | Safe | Dims are in memory; a reminted session starts at the request's cols/rows (80x24 for spawn-on-create) | A resize on an exited-but-mapped session is a silent no-op ok |
| `terminal.reclaim` | `sessionId` field required; the session need not exist | Idempotent: a second call reports `restored: false` | n/a | Restores `desktop_dims` if held, seats `SessionDriver::Desktop`, broadcasts `terminalDriverChanged`, replies `{restored}` | Safe | Driver state is in memory | Desktop only: mobile callers get a typed refusal |
| `terminal.driver.list` | none | Read | n/a | Read only: one `{sessionId, driver}` row per live session | Safe | In memory | n/a |
| `terminal.runningProcesses` | `sessionId` field required; the session need not exist | Read | n/a | Read only: samples the sealed shell's process tree, empty for unknown or exited sessions | Safe | In memory | n/a |

## Reads and resync

| Operation | Instance check | Replay | Same id + different payload | Commit vs publish | Lost reply retry | Restart recovery | Stale owner / wrong actor |
|---|---|---|---|---|---|---|---|
| `terminal.read` | `require_session` | Read | n/a | Read over the live ring buffer (not the history store): returns `handle`, `running`, `baseCursor`, `cursor`, `nextCursor`, `truncated`, `text`, `dataBase64` | Safe | Reads what the live session retains; a reminted session's ring starts at the restored scrollback | A `cursor` below the retained `baseCursor` clamps to base and reports `truncated: true`; windows are aligned to UTF-8 scalar boundaries |
| `setOutputPaused` | `require_session` | Pause is idempotent; unpause resumes from the cursor | n/a | Flushes pending output first; `paused: false` sends the missed delta on the terminal lane ahead of the control-lane reply and returns `{delta: true, resumed}`; with no cursor or an unprovable gap it returns a snapshot resend (`delta: false`, `resetInteractionModes: true`, capped at `restore_snapshot_bytes`) and seats the cursor at the stream end. A rejected delta send keeps the client paused and the resync timer armed | Safe; a repeated unpause recomputes from the cursor | Cursors are in memory; a reattached client starts at the stream end | Only accepted terminal frames advance the cursor, so a dropped frame is exactly what the next resume resends; a closed lane schedules the client's disconnect |

## Detach and terminate

| Operation | Instance check | Replay | Same id + different payload | Commit vs publish | Lost reply retry | Restart recovery | Stale owner / wrong actor |
|---|---|---|---|---|---|---|---|
| `detach` | `require_session` | Idempotent for a client that is not attached | n/a | Flush output, detach (drops the delivery cursor), release the client's mobile claim for that session (restoring `desktop_dims`), `immediate_checkpoint`, then reply | A retry against a live session is a no-op ok; a retry after termination errors `not attached` | The checkpoint detach just wrote is the recovery state | Detach frees the phone's seat for that session only; other sessions it drives keep their claim |
| `terminate` | `require_session` | Not idempotent at the request layer: a retry errors `Terminal session is not attached: {id}` | n/a | Exit push + orchestration cleanup first; when the tab row exists, `remove_terminal_session_tab` deletes the row, records workspace activity, flushes + awaits durable writes, removes the session, `terminate(true)` deletes checkpoint and chunks, then `workspaceTabsChanged` + `workspaceActivityChanged` broadcast; without a tab row the same teardown runs minus the broadcasts. The reply goes out after all of it | Typed `not attached` error; the client cannot distinguish "already terminated" from "never attached" | History is deliberately deleted; nothing remains to recover | Blocked while a runtime mutation is outstanding; workspace/tab removal mutations reach the same teardown through `terminate_sessions` |

## Terminal Pulse

| Operation | Instance check | Replay | Same id + different payload | Commit vs publish | Lost reply retry | Restart recovery | Stale owner / wrong actor |
|---|---|---|---|---|---|---|---|
| `terminal.pulse.status` | `require_session`; not on the mobile allowlist | Read | n/a | Read only: `configuration` from the tab's `payload.terminalPulse` (defaults `r` + Enter + 2000 ms) and `armed` from the in-memory rule | Safe | Persisted config survives; `armed` is in memory and reads false until a fresh configure | `armed` compares the session instance id, so a rule never reports armed for a reminted session |
| `terminal.pulse.configure` | `require_session`; local only; `configuration` must validate (`command` non-empty, at most 4096 bytes; delay 100..=3600000 ms); `armed: true` also requires a running session and an existing workspace | A value write into the tab payload plus an arm/disarm; a second configure while a watcher start is pending supersedes the first, which errors `Terminal Pulse configuration was superseded.` | Last write wins on the tab payload | Persist `terminalPulse` on the tab, then arm/disarm the in-memory rule, then `workspaceTabsChanged` + `terminalPulseChanged` broadcasts, then the reply. A session that changed mid-flight (workspace/tab/instance, or stopped running when armed) errors `Terminal Pulse configuration became stale after the terminal changed.` | Re-applying the same config is safe | The watcher and rule are in memory; a restart or remint disarms the rule, and a due write under a stale instance id or generation is dropped | A watcher failure disarms every rule in the workspace; a backpressured pulse write retries on a 50 ms schedule under a new generation |

## Internal machinery

These are not requests, but the matrix columns above rely on them.

| Mechanism | Contract |
|---|---|
| PTY output | `handle_pty_output` appends to the scrollback and arms two independent batch tracks: `output_batch` (8 ms debounce or 64 KiB early flush) for client delivery and `durable_output_batch` (100 ms or 64 KiB) for `outputChunks` persistence, plus the debounced checkpoint timer |
| Output delivery | `flush_output_batch` pushes one `ClientFrame::Output` per attached, non-paused client on the bounded terminal lane (8 frames local, 32 mobile). Only an accepted frame advances that client's delivery cursor. A `Full` lane marks the client paused + resync-pending and arms a resync timer; a `Closed` lane schedules disconnect |
| `OutputResyncTick` | Emits `outputResyncRequired` on the terminal lane while the flag is pending; `Full` reschedules, `Closed` clears the flag and schedules disconnect. The client answers with `setOutputPaused` false, and a restart-resynced client always lands on the snapshot path because `attach_for_resync` dropped its cursor |
| Durable output | `persist_output_batch` runs `append_output(sessionId, sequence, data)` off the actor loop, tracked in `pending_output_writes` for the `await_output_writes` barrier (2 s). `append_output` only inserts while a `checkpoints` row exists, which is why `Session::start` writes its checkpoint before the session is reachable |
| Checkpoints | `CheckpointTick` (5 s debounce), `immediate_checkpoint` (detach, kept-on-exit, disconnect, dispose), and `handle_checkpoint_tick` all flush durable output, await pending writes, `write_checkpoint`, then `trim_session(scrollback_bytes)`. `terminate(false)` writes a final checkpoint; `terminate(true)` deletes checkpoint + chunks |
| PTY exit | `handle_session_exit` disarms the pulse, queues the exit push, cleans orchestration state; `Session::handle_exit` returns `None` on an already-exited session so a second event is a no-op. A kept failed setup or failed owned spawn gets `immediate_checkpoint`; otherwise `remove_terminal_session_tab` retires tab + session + history. When the tab row is already gone the session stays in the map not-running with a final checkpoint, and a later attach remints it |
| Client disconnect | `dispose_client` drops the client's orchestration waiters, cancels its queued runtime mutations, releases its mobile driver claims (restoring `desktop_dims`), cancels prompt uploads, detaches it from every session (forgetting delivery cursors), `immediate_checkpoint`s each session, then re-arms idle shutdown. The PTY survives: no client disconnect kills a session |
| Idle shutdown | `schedule_shutdown_if_idle` arms `empty_shutdown_delay_seconds` (30 s) when nothing runs and `detached_session_shutdown_delay_seconds` (3600 s) while sessions run; persistent mode, authenticated clients, jobs, mutations, the mobile gateway, coordinators, push subscriptions, and automations all cancel it. `handle_shutdown_tick` is generation-guarded: a stale tick is ignored, and a current tick runs `dispose()`, which terminates every session with `remove_history = false` so the final checkpoint and chunks survive for the next host start |
| `host.shutdown` / `host.restart` | Non-forced calls fail while agents, sessions, jobs, or push subscriptions are active; the reply is written before disposal through the ordered `ShutdownRuntimeAfterWrite`/`RestartRuntimeAfterWrite` markers. Mobile clients cannot call `host.shutdown` |
| Startup recovery | `reconcile_spawn_on_create_tabs` walks every workspace's tabs; a `kind = "terminal"` tab with `payload.spawnOnCreate == true` re-arms after-ready prompts, requires an `Active` workspace, and respawns through `take_terminal_restart_state` + `start_new_terminal_session` at 80x24. A failed restore removes the tab row. Tabs without `spawnOnCreate` are not respawned; their PTY appears on the next attach. `upsert_workspace_tab_and_spawn` rolls back the tab row and terminates its sessions when a spawn fails |
| Startup input | `TerminalStartupInput`, `TerminalStartupSubmit`, and `OrchestrationDeferredEnter` carry the session instance id captured at schedule time; the handler drops the write when the session's instance id no longer matches or it stopped running |
| `Session::restore_exited` | Rebuilds a not-running session from `checkpoints` + `outputChunks` ordered by `(sequence, id)`, resuming `output_stream_bytes` at the persisted absolute position. A checkpoint without `ended_at` restores as interrupted with exit code -1 |

## Known gaps

- `createOrAttach` and `terminal.attach` never re-validate `workspaceId`/`tabId`/`workingDirectory`/`launch` against a live session; only `terminal.restart` checks metadata. A caller holding a stale but valid handle attaches to whatever PTY the handle names.
- `write` has no op id: a lost reply leaves the client unable to tell whether the PTY consumed the bytes, and a retry duplicates the input.
- `terminal_input_backpressure` travels as a `State` error string prefix, not a typed `Conflict` code; the host string-matches it for orchestration Enter and Terminal Pulse retries.
- `terminate` is not idempotent at the request layer: a retry reports `not attached`, the same error a never-attached handle produces.
- On the dead-handle path of `createOrAttach`, `take_terminal_restart_state` drops the old session (history preserved) before `launch` is validated, so a malformed launch still consumes the old PTY; the next call restores from the checkpoint.
- An exited session whose tab row was already removed stays in `sessions` as a not-running entry until an attach remints it or the host shuts down; `terminal.read` still serves its retained ring and `write` fails `not running`.
- Terminal Pulse configuration is persisted on the tab, but the armed rule is in memory: after a host restart `armed` reads false until the next `terminal.pulse.configure`.
