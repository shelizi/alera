# Alera Release Matrix 現況地圖

日期：2026-09-13。程式碼基準：482a25da。分支：docs/release-matrix。

這是一份純盤點文件，目的是為 section 21 Phase 5 release/portable work 提供集中化前的現況輸入。既有路線文件將 Phase 5 留為 observability 與 release matrix，並要求把 desktop、runtime、mobile、landing 與 package metadata 放入同一張矩陣（docs/handoff-architecture-refactor-2026-09-11.md:1485；docs/architecture-review-2026-09-11.md:160）。

## 1. 範圍與讀法

盤點範圍包含 .github/workflows/、.github/actions/、.github/AGENTS.md、Windows/macOS/Linux packaging、rust_builder/、mobile/、rust/、tool/release/、既有 release 文件與 landing/。主表面是 Windows desktop、macOS、Linux、standalone runtime/node、mobile 五類；Windows 依 portable 與 installable package-manager 路徑拆成兩列，因此矩陣共有六列。

本文件的「artifact」是 CI 實際產出或發布的檔案；「建置入口」是 workflow、script、CMake 或 Xcode 中可追溯的入口；「metadata」包含版本、tag、descriptor、hash、landing data 與 package-manager/repository metadata。表格每個含有來源敘述的 cell 都附上已核對的 file:line 參考。

計數以「不同的持續維護位置，或由 CI 產生且對外承載該事實的邏輯落點」為單位；同一檔案中的讀取、驗證與傳遞不重複計數，三個同構平台 fragment 視為一個 fragment family，外部 GitHub、R2、package repository 目的地則各自計為一個發布落點。這是風險盤點的相對數字，不是檔案行數統計。

## 2. 現況總覽

- Cut Release 是 stable/rc 的手動發布入口，先為 desktop 與 mobile 分別計畫 artifact version、release version、build number 與 tag，再由 version PR 寫入相應版本檔案（.github/workflows/release-cut.yml:1-143）。
- 此 checkout 的版本快照是 root desktop 0.82.0+257、mobile 0.33.3+248；prepared release snapshot 標記 desktop v0.82.0/build 257 應發布，mobile 此次不發布，landing data 則仍各自記錄 desktop v0.82.0 與 mobile v0.33.3（pubspec.yaml:1-8；mobile/pubspec.yaml:7-19；tool/release/prepared_release.json:1-20；landing/src/data/releases.json:1-10）。
- desktop native job 建立 macOS arm64、Windows x64、Linux x64 三個平台 bundle，另外的 cross job 建立 macOS x64、Windows arm64、Linux arm64 三個 runtime sidecar 輸入，兩者最後合成六個 platform/architecture runtime archive（.github/workflows/release-cut.yml:326-612；.github/workflows/release-cut.yml:626-870；.github/workflows/release-cut.yml:801-870）。
- mobile release job 只在 release-cut 產出四個 Android APK 及其 hash sidecar；mobile CI 另行驗證 Android 與未簽名 iOS build，landing 目前把 iOS 標成尚未提供（.github/workflows/release-cut.yml:871-999；.github/workflows/mobile-build.yml:70-88；landing/src/pages/download.astro:331-343）。
- publish job 下載並驗證 desktop、runtime、Android 產物，合併 desktop update indexes、建立並簽署 runtime archive、建立 Linux APT/RPM repository metadata，再建立 GitHub Release、同步 R2 與發布 stable package-manager manifests（.github/workflows/release-cut.yml:1000-1533；.github/workflows/release-cut.yml:1535-1700）。
- landing 是獨立的 Astro/Bun static build，landing/src/data/releases.json 是下載頁的 desktop/mobile release data；release-cut 的 stable version PR 會更新它，但 landing workflow 本身只負責建置與部署檢查（.github/workflows/landing.yml:23-60；tool/release/update_landing_release_links.dart:10-68）。
- native library 與 sidecar 是兩條相鄰路徑：Linux/Windows 的 rust_builder Cargokit 接入 alera_native，macOS 由 podspec 接入，平台 CMake/Xcode hook 另行建置 alera-cli sidecar（rust_builder/linux/CMakeLists.txt:10-18；rust_builder/windows/CMakeLists.txt:11-19；rust_builder/macos/alera_native.podspec:29-37；windows/CMakeLists.txt:67-149；macos/Runner.xcodeproj/project.pbxproj:395-412）。
- 共用 CI prologue 由 setup-flutter-workspace 提供 Flutter 3.47.2、平台依賴、可選 Rust/sccache 與 preflight；setup-rust-sccache 固定 Rust 1.98.0 並只設 RUSTC_WRAPPER=sccache，Windows tune action 再建立 R:\c scratch mapping 與 Cargokit temp layout；warm-cache 是 Cargokit cache 的保存入口（.github/actions/setup-flutter-workspace/action.yml:60-81；.github/actions/setup-flutter-workspace/action.yml:195-217；.github/actions/setup-rust-sccache/action.yml:9-37；.github/actions/tune-windows-build/action.yml:32-76；.github/workflows/warm-cache.yml:43-97）。

## 4. 散落點與風險盤點

### 4.1 版本、tag 與 build number

- Desktop release identity 目前有 7 個邏輯落點：root pubspec.yaml 的 version；release_plan.dart 的計算與 GitHub outputs；prepared_release.json 的 prepared snapshot；Git tag；landing desktop data；desktop update descriptors/index；GitHub Release title/assets（pubspec.yaml:4；tool/release/release_plan.dart:135-146；tool/release/release_plan.dart:222-269；tool/release/prepared_release.json:1-11；tool/release/release_plan.dart:60-75；.github/workflows/release-cut.yml:1208-1241；landing/src/data/releases.json:1-5；.github/workflows/release-cut.yml:438-456；.github/workflows/release-cut.yml:1095-1113；.github/workflows/release-cut.yml:1243-1330）。
- Mobile release identity 目前有 7 個邏輯落點：mobile/pubspec.yaml；mobile plan/output；prepared snapshot schema；mobile Git tag；landing mobile data；APK filenames；mobile GitHub Release title/assets（mobile/pubspec.yaml:7-19；tool/release/release_plan.dart:135-146；tool/release/release_plan.dart:258-262；tool/release/prepared_release.json:12-20；tool/release/release_plan.dart:60-75；.github/workflows/release-cut.yml:973-998；landing/src/data/releases.json:6-10；.github/workflows/release-cut.yml:1281-1341）。
- Rust crate version 是另一組 3 個 Cargo 落點，不應與產品 release version 混為一談：workspace root package、alera-cli package 與 committed lock entry 都是 0.1.0（rust/Cargo.toml:1-15；rust/alera-cli/Cargo.toml:1-10；rust/Cargo.lock:65-66；rust/Cargo.lock:157-158）。
- landing package 自己還有 landing/package.json 的 0.0.1，它是網站 package identity，不是 Alera desktop/mobile release version，但同樣會出現在版本搜尋與維運視線中（landing/package.json:1-9；landing/src/data/releases.json:1-10）。

### 4.2 Release manifest、descriptor 與 hash

- Desktop update descriptor 有 5 個邏輯落點：desktop_updater.yaml 的 policy/base URL；三個 platform release.json 生成物 family；三個 update-index fragment family；channel merged app-archive.json；同步到 R2 的 public update path（desktop_updater.yaml:1-14；.github/workflows/release-cut.yml:419-456；.github/workflows/release-cut.yml:458-490；.github/workflows/release-cut.yml:1095-1113；.github/workflows/release-cut.yml:1397-1419）。
- Runtime descriptor 是另一條 3 個邏輯落點：每個 sidecar tarball 內的 manifest；runtime-archive.json 或 rc 版本；GitHub Release public asset（由 publish job sign/verify）（tool/release/package_runtime_sidecars.dart:59-86；tool/release/build_runtime_archive.dart:84-98；.github/workflows/release-cut.yml:1115-1135；docs/release-trust.md:55-55）。
- Hash 目前分成 7 個 artifact metadata family：desktop release.json 的 SHA-256/length；runtime tarball .sha256；runtime archive JSON item hash/size；Android APK .sha256；Homebrew/Scoop/Chocolatey manifest checksums；APT Packages；RPM repomd.xml（tool/release/verify_desktop_update_channel.dart:83-109；tool/release/package_runtime_sidecars.dart:79-86；tool/release/build_runtime_archive.dart:60-68；.github/workflows/release-cut.yml:986-990；tool/release/render_package_manifests.dart:91-124；tool/release/build_linux_repositories.sh:108-132）。
- 對外 hash 的同一來源仍被多個 formatter 與 repository metadata 重新承載：package-manager render 接收兩個 desktop checksum，Linux repository 再生成自己的索引鏈，mobile/runtime 另生成 sidecar；目前沒有一個跨 desktop、runtime、mobile、APT/RPM 與 package-manager 的 artifact catalog（.github/workflows/release-cut.yml:1568-1586；tool/release/render_package_manifests.dart:91-124；tool/release/build_linux_repositories.sh:108-132；.github/workflows/release-cut.yml:986-990）。

### 4.3 Changelog 與 release notes

- 產品 release notes 的來源邏輯是 generate_release_notes.dart，它依 product scope 讀 Git history 並輸出 notes；desktop 與 mobile 由 publish job 分別呼叫，最後各自成為 GitHub Release body（tool/release/generate_release_notes.dart:6-42；.github/workflows/release-cut.yml:1243-1317）。
- 目前 scoped product paths 沒有找到 canonical CHANGELOG 或 HISTORY 檔；repository 中可見的 CHANGELOG 主要位於 third-party packages，不能直接視為 Alera release notes（tool/release/generate_release_notes.dart:6-11；third_party/dart_terminal/pkgs/pty/portable_pty/CHANGELOG.md:1-5；third_party/xterm/CHANGELOG.md:1-5）。
- 因此 release notes 有 3 個邏輯落點：notes generator；desktop GitHub Release body；mobile GitHub Release body。landing download page 顯示版本與下載資訊，但不是 changelog source（tool/release/generate_release_notes.dart:125-141；.github/workflows/release-cut.yml:1243-1279；.github/workflows/release-cut.yml:1281-1317；landing/src/pages/download.astro:154-180；landing/src/pages/download.astro:296-328）。

### 4.4 Package-manager 與 Linux repository manifests

- Desktop package-manager metadata 有 7 個邏輯落點：tool/release/render_package_manifests.dart 的 renderer；packaging/ 的 Homebrew/Scoop/Chocolatey templates family；每次 release 的 packaging-out；Homebrew tap；Scoop bucket；Chocolatey package source/feed；landing page 的 package-manager commands（tool/release/render_package_manifests.dart:66-124；packaging/homebrew/alera.rb.tmpl:1-32；packaging/scoop/alera.json.tmpl:1-30；packaging/chocolatey/alera.nuspec.tmpl:3-37；.github/workflows/release-cut.yml:1568-1586；.github/workflows/release-cut.yml:1588-1700；landing/src/pages/download.astro:24-30）。
- Linux package/repository metadata 有 4 個邏輯落點：package_linux.sh 中的 deb/rpm control/spec；build_linux_repositories.sh 產出的 APT/RPM index；landing download page 的 apt/dnf instructions；landing/public/install.sh 的 repository/keyring setup（tool/release/package_linux.sh:53-133；tool/release/build_linux_repositories.sh:89-132；landing/src/pages/download.astro:42-55；landing/public/install.sh:19-22；landing/public/install.sh:267-300）。
- Package-manager 與 repository 發布是 stable-only 的 downstream jobs，且 package manifest failure 不回滾已公開 release；這使其成為與 GitHub Release、R2、landing 之間的操作順序與失敗語意落點（.github/workflows/release-cut.yml:1535-1549；.github/workflows/release-cut.yml:1639-1700；docs/release-trust.md:31-39）。

## 5. 集中化建議

以下是針對現況的 source-of-truth 建議，不是本文件的實作計畫，也不改變既有 workflow 行為。

| 事實 | 建議的 single source of truth | 現有位置的建議角色 |
| --- | --- | --- |
| Desktop/mobile 的 artifact version、release version、build number、channel、tag 與 previous tag | 以 prepared_release schema 為候選 canonical release plan，讓它成為兩個 product 的同一份 release identity record；release_plan.dart 只負責計算與產出（tool/release/prepared_release.dart:38-106；tool/release/prepared_release.json:1-20；tool/release/release_plan.dart:135-146） | root pubspec.yaml 與 mobile/pubspec.yaml 是版本投影與 build input，Git tag、landing data、GitHub Release 與 update metadata 是發布投影（.github/workflows/release-cut.yml:193-229；.github/workflows/release-cut.yml:1208-1241） |

### 建議遷移順序

1. 先凍結現況 contract 與計數規則，將 desktop/mobile、runtime、package、repository、landing 與 notes 的欄位名稱和 channel semantics 對齊；此文件作為 Phase 5 的 baseline（.github/AGENTS.md:31-41；docs/architecture-review-2026-09-11.md:160）。
2. 先集中 release identity：以 prepared_release 為候選 schema，確認 desktop/mobile version、build、tag 與 previous tag 的唯一讀取方向，再保留 pubspec 更新作為 adapter（tool/release/prepared_release.dart:97-106；tool/release/prepared_release.dart:233-267）。
3. 再集中 artifact catalog 與 hash：把三個 native desktop、三個 cross runtime、四個 Android APK、deb/rpm/tar 的完成結果統一登錄，再由 signed desktop/runtime descriptors 與 package outputs 投影（.github/workflows/release-cut.yml:458-612；.github/workflows/release-cut.yml:626-870；.github/workflows/release-cut.yml:935-990）。
4. 再接通 package-manager 與 APT/RPM repository metadata，讓 template renderer 與 repository builder 只接受 catalog，不自行重建版本與 hash；維持 stable-after-public-release 的順序（.github/workflows/release-cut.yml:1095-1142；.github/workflows/release-cut.yml:1535-1586；tool/release/build_linux_repositories.sh:108-132）。
5. 最後集中 notes、landing release links、download URLs 與 installer instructions，讓 landing 與 GitHub Release 只消費同一份 product-scoped release data，完成後才移除舊的重複欄位（tool/release/update_landing_release_links.dart:24-68；tool/release/generate_release_notes.dart:125-141；landing/src/pages/download.astro:20-55）。
6. 以 stable、rc、desktop-only、mobile-only、缺少 signing secret、package publish failure 與 R2 failure 做 cutover verification，確認每個 projection 的版本、hash、tag、URL 與 signature 一致，再決定哪些舊落點可退役（.github/AGENTS.md:33-41；.github/workflows/release-cut.yml:1486-1533）。
