# GPUI New Agent detection/dropdown parity audit (2026-11-12)

## Classic reference
- `lib/src/features/workbench/presentation/workspace_workbench_new_tab_button.dart` shows `installedAgentClisProvider` (machine-local binary discovery), not just Host Agent Profiles.
- `lib/src/features/agent_profiles/application/local_agent_detection.dart` probes the canonical descriptor order, Windows PATH/PATHEXT, Classic's explicit executable overrides, and a bounded `--version` health check for AGY only.
- Classic's selection directly creates a Terminal with a configured initial local Agent launch. This is **not** the same as Native's Host profile launch mechanism.

## Defects found in Native before this patch
1. The `+` menu projected only Host Agent Profiles, so Host-offline or no-profile installations showed no Agents even when local binaries were installed.
2. It queried Host Agent Profiles only after the menu had opened, so a first popup could show a stale snapshot.
3. No independent machine-local CLI inventory was maintained.

## Implemented
- Read-only local binary detection in `desktop_gpui/src/local_agent_detection.rs`, using Rust Core `AGENT_DESCRIPTORS` for canonical names/order.
- Windows PATH/PATHEXT and quoted PATH entries, custom override argument with invalid-override fail-closed behavior, and windowless/timeout-bounded AGY `--version`.
- Startup background inventory and explicit dropdown rescan. The inventory is machine-wide and independent of the Host Profile request state. Both primary and secondary `+` menus show an **Installed Agent CLIs** group, with Host Profiles remaining in their own group.
- Selecting a detected local Agent now uses the existing Host-managed Terminal tab creation, **without requiring a saved Agent Profile**. It calls bounded `terminal --no-start create-agent` and authenticated `tab.upsert`, passing the concrete detected Agent executable (not shell text). For direct launches, GPUI now first validates the Host's persisted tab **Agent type, exact executable, no additional arguments and spawn flag** plus the Host tab/workspace/session identity. It then requires the exact **running** session, rejecting conflicting Hook Agent types while allowing a missing Hook status during initial PTY startup.
- Host Agent Profiles remain separate in the menu, with their task composer unchanged. Native Settings > Agent Profiles now has Agent executable path Save/Clear controls, atomic CAS/readback and inventory rescan; Classic's private settings are not modified.

## Native Host create journal across GUI restart (2026-11-12)
- **Risk addressed:** `TerminalCreateFlow` formerly existed only in memory; after GUI restart it returned to `Idle` even if a previous `terminal create`/`terminal create-agent` RPC had committed a PTY and lost its reply. A blind retry could create a duplicate. A Host-side exactly-once token is still not implemented.
- **Persistent Native fence:** for each *canonical workspace*, Native now creates a bounded, versioned `host-create-<workspace-hash>.json` under its own `PreviewSessionStore` state dir before ANY side-effecting Host create call. The record contains only root, nonce and optional canonical Agent ID; no executable arguments, credentials, prompt or terminal text. `create_new` is atomic across two local Native windows, and the file is flushed with `sync_all` before Host RPC. A partial/corrupt journal fails closed; Git fixtures and Classic RuntimeStore are unchanged.
- **GUI startup / workspace switching:** reloads the marker into `TerminalCreateFlow::OutcomeUnknown`; the `+` menu blocks both New Terminal and New Agent and permits only Host session listing/Attach. A delayed Host callback cannot be used as authority after workspace changes. Normal completion retires only the matching nonce after an authenticated exact running Session/Workspace/Tab confirmation. Unknown/timeout manual dismissal now requires a successful authenticated Host list (and refuses to dismiss while the live in-process create RPC is still pending).
- **TDD RED/GREEN:** `unconfirmed_host_create_survives_restart_and_blocks_duplicate_shell`, `corrupted_or_concurrent_host_create_journal_fails_closed_and_is_workspace_scoped`, and `recovered_create_outcome_never_reissues_a_host_create` all passed. Full Native `cargo test --offline --locked`: **512/512 Library**, **31/31 Native binary**, 3 environment-gated integration tests ignored.
- **Real isolated Host E2E (1/1 PASS):** expanded opt-in `terminal_bootstrap_host` to reserve the marker before creating a real PTY in a unique temporary Runtime. After confirming that PTY was listed as running, dropped the first GUI state object and instantiated another from the same directory. It recovered the marker, refused to reserve another create, did not auto-attach or auto-create, and only allowed clearing the marker after a real authenticated Host list; the same original PTY was preserved. This simulates loss of the Native view after Host commit, not an OS-killed GPUI process or a server crash. Cleanup stops only the temporary Host.
- **Open gates:** truly server-enforced idempotency for a request that is still executing *after another view explicitly dismisses its recovery record*, actual OS-kill-at-the-RPC-boundary GUI test, multiple-window manual acknowledgement races, direct Agent Profile launch path, Host crash/restart during create, other providers, notifications, DPI, and POSIX/macOS parity. This is a conservative client-side fence, not exactly-once Host semantics. Keep `supported=false`; no main merge, Push or release.
