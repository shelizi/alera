# Tab and layout operation contract

This table answers the eight transaction/replay questions from the architecture refactor handoff (section 13) for every `tab.*` and `layout.*` request handled by `ServerActor`. Companion to `orchestration-operation-contract.md`, `project-operation-contract.md`, and `workspace-operation-contract.md`; update the table and its pinning tests together.

Authority is `ServerActor` on the terminal-host mailbox, persisting through `RuntimeStore`. Tabs are special in two ways: their `payload` carries host-owned fields (`agentTitle*` state) that client writes must not clobber, and `kind = "terminal"` tabs with `payload.spawnOnCreate` own a live PTY that is spawned as part of the upsert.

## Tabs

| Operation | Instance check | Replay | Same id + different payload | Commit vs publish | Lost reply retry | Restart recovery | Stale owner / wrong actor |
|---|---|---|---|---|---|---|---|
| `tab.list` / `tab.find` | Workspace/tab id | Read; rows pass through `workspace_tab_for_client` so mobile and desktop get different projections (host-owned prompt/pulse fields redacted where required) | n/a | Read only | Safe | Persisted | Per-client projection prevents a mobile client from observing desktop-only fields |
| `tab.upsert` | Existing row's host-owned payload keys are preserved over the client payload (`preserve_host_owned_tab_payload`); a changed `agentTitleRevision` cancels the in-flight title job | Value write, but not a transfer | Last write wins for client-owned fields **except** a terminal whose stored `workspaceId` is different: this is refused, not silently moved | Row commits, then `spawnOnCreate` spawn runs; a spawn failure ordinarily removes the tab, but a transferred terminal is retained by Host startup reconciliation if original directory recovery fails | Retry only within the same workspace; do not retry as a transfer | `reconcile_spawn_on_create_tabs` retries the stored original launch directory for moved tabs and preserves their row on unsafe restore failure | Transfer receipt, original launch workspace/directory and Host-owned fields are retained; `tab.transfer` is the only cross-workspace owner change |
| `tab.rename` | Tab must exist | Value write | Last write wins | Rename commits (after cancelling the title job), then `workspaceTabsChanged(workspace)` broadcast | Safe | Persisted | n/a |
| `tab.remove` | Runtime mutation; for a moved Terminal carrying a transfer receipt, `expectedWorkspaceId` must match its current owner; a rejected stale close does **not** cancel its title job | Idempotent after ownership checks: `RemoveTab` deletes the matching row; a second legitimate call finds nothing | n/a | Delete commits in the worker; `TabRemoved` effect then closes its Session on the actor | Replay with the **same** scoped `expectedWorkspaceId`, never an unscoped delete from an obsolete window | Persisted | An old workspace's stale close is refused for transferred Tabs |
| `tab.removeForWorkspace` | Runtime mutation | Idempotent: routes to `sleep_workspace`, deleting `workspaceTabs` + `workbenchLayouts` in one transaction | n/a | Cascade commits first; `WorkspaceTabsRemoved` effect follows | Safe | Persisted | n/a |
| `tab.transfer` | Authenticated desktop Host; existing live PTY, exact Tab/Session, two active workspaces on one Host, no Pulse/automation/active dispatch, no conflicting runtime mutation | Exact `clientMutationId` receipt identifies one source/target move; do **not** mint another on timeout | Changed mutation ID does not validate the previous operation; requires a fresh, authoritative plan | Store CAS atomically updates Tab owner and both Layouts; Actor then reassigns **existing live Session owner** and broadcasts both sides; PTY/process/output unchanged | `tab.transfer.status` confirms exact receipt **and live PTY owner**; otherwise outcome remains unknown and further same-Tab moves are blocked | Persisted Tab/Layout survives; live PTY does not survive Host restart, remint must honor original launch path | Feature remains disabled to UI: `tab.transfer.capabilities.supported=false`; do not claim full transfer availability |
| `tab.transfer.status` / `tab.transfer.capabilities` | Authenticated Host; status requires operation identity and live Session | Read only | n/a | Status returns applied only for matching persisted receipt and current live owner; capabilities truthfully reports `supported:false` | Safe to re-query | Live PTY proof is unavailable until a Session exists | Old Hosts without capability route must disable Drop |

## Layouts

| Operation | Instance check | Replay | Same id + different payload | Commit vs publish | Lost reply retry | Restart recovery | Stale owner / wrong actor |
|---|---|---|---|---|---|---|---|
| `layout.find` | Workspace id | Read | n/a | Read only | Safe | Persisted | n/a |
| `layout.upsert` | One row per workspace; for transferred Terminal tabs, Store checks their **current owner** inside the same SQLite transaction as the layout write | Value write with transferred Terminal membership fence | Last write wins for legacy/non-transferred layout content; **stale pre-transfer snapshots that remove a moved Tab from destination or resurrect it at source fail** | Transactional ownership guard then upsert, then `workbenchLayoutsChanged` | Safe to retry only after authoritative Layout refresh when a transfer mismatch is rejected | Persisted | Narrow moved-Tab membership guard, **not** full revisioned CAS for all Layout fields |
| `layout.remove` | Workspace id | Delete of a missing row is a no-op | n/a | Delete, then `workbenchLayoutsChanged` broadcast | Safe | Persisted | n/a |

Invariants worth keeping visible:

- A `tab.upsert` that fails its `spawnOnCreate` spawn leaves no tab row and no session; the rollback order is remove-row then terminate-sessions.
- `tab.remove` cancels the agent-title job on the actor before the mutation is enqueued, so an in-flight title write cannot resurrect a removed tab's title state.
- Startup reconciliation ordinarily removes a failed spawn-on-create row, **except** a previously transferred Terminal: a missing original launch directory or unsafe remint keeps the Tab row for recovery rather than destroying its durable ownership.
- Layout writes from legacy clients must not overwrite terminal ownership already transferred by a separate window; the Store's D3 membership fence is enforced even when the Flutter watcher did not run.
