## 用户核心目标

- Make Alera side-by-side diffs align corresponding rows like common diff tools while preserving read-only/non-savable modes.

## 已确认事实

- Read-only/staged/full-file side-by-side already uses paired row projection with null cells, so it already has alignment semantics and must remain non-editable.
- The misalignment was isolated to editable working-tree full-file side-by-side, which used two raw TextFields synchronized only by pixel scroll.
- CodeForge supports display-only VirtualRemovedBlock rows via setGitDiffDecorations, suitable for inserting spacer rows without modifying saved document text.
- Widget test runner does not have code_forge.dll, so editable diff now falls back to the existing pure-Flutter TextField path when the CodeForge native runtime is unavailable; normal Alera startup initializes CodeForge Rust before runApp.
- Before commit, unrelated editor changes were detected staged concurrently and were explicitly unstaged while preserving their working-tree content.
- The final commit contains exactly the four intended side-by-side diff files.
- Those editor changes were the separate in-file search feature, not part of side-by-side diff alignment.
- They have since been committed separately as 4bcd8deb feat(editor): add in-file search.
- The commit added workspace_editor_find.dart, modified workspace_editor_surface.dart, and updated workspace_editor_surface_test.dart.
- Current tracked working tree is clean for these editor files; only untracked build/worktree/history artifacts remain.
