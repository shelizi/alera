## 用户核心目标

- Confirm whether inactive Alera terminals buffer output in memory and render it in a burst when switched active.
- Clarify whether the intermediate terminal output/process disappears while an inactive terminal is paused and later resumed.
- Implement lossless inactive-terminal output buffering: inactive tabs should avoid continuous rendering, overflow should be parsed into xterm instead of discarded, then pending should reset and accumulate again; revealing a tab should catch up immediately rather than visibly replaying a burst.

## 已确认事实

- Inactive/hidden terminal output is intentionally not flushed to xterm while isOutputVisible is false; _TerminalSessionOutputPump.scheduleFlush returns early and preserves the backlog.
- Client-side pending output is stored as queued _TerminalOutputSegment chunks in memory. Live pending output is capped at 1 MiB and drained at up to 64 KiB per frame with a 50 ms minimum flush interval (about 20 fps sustained).
- Visibility accounting schedules the backlog flush again when the terminal becomes visible.
- The terminal-host PTY path also pauses host output delivery for hidden terminals. Output racing before pause takes effect is queued client-side; output missed while paused is resynchronized by the host on resume as a delta when possible or a snapshot otherwise.
- Therefore the visible burst on tab activation is a catch-up from memory/host retained output, normally spread across several frames rather than literally one single render call.
- Normally the intermediate output does not disappear. The host tracks a per-client delivered_output_cursor and, on resume, sends exactly the missed byte range when that cursor still lies inside the retained output ring.
- If the retained ring has already trimmed past the paused client's cursor, Alera cannot reconstruct the exact missed byte sequence and deliberately falls back to a snapshot. In that fallback path, intermediate output older than the retained/snapshot tail is no longer replayed into the emulator.
- The current host-side scrollback retention default is 10,000,000 bytes, and the default restore snapshot budget is the same. Alera's TerminalSettings also defaults hostScrollbackBytes to 10,000,000 bytes.
- The output resume tests explicitly verify both paths: delta resume preserves the missed ' world' bytes, while an overrun ring falls back to the retained tail snapshot; snapshot replay is additionally capped by restore_snapshot_bytes.
- xterm itself still has bounded scrollback; after deliberately huge parsed output, old visible lines can naturally roll out of xterm even though no pending bytes were dropped. The regression therefore verifies terminal mode state to prove the formerly trimmed prefix was parsed.
- The previous partial-restore backpressure test encoded the old lossy behavior and was updated to verify lossless overflow instead.
- A pre-existing dirty process-exit regression referenced a nonexistent factory.sessions getter; it was fixed by constructing and retaining the fake PTY session explicitly.

## 关键设计决定

- Inactive terminal tabs no longer pause Terminal Host delivery while the app remains foregrounded; only whole-app backgrounding pauses Host output.
- The 1 MiB client pending threshold is now an accumulation window, not a discard cap: when live pending exceeds it, the entire queued stream is synchronously parsed into the terminal emulator, pending is cleared, and accumulation restarts.
- When a hidden terminal becomes visible, its remaining pending output is flushed before the first revealed frame to avoid visible fast-scroll catch-up.
- Host pause/resume state is tracked optimistically so rapid foreground transitions stay ordered, with rollback on a failed non-superseded request so a later sync can retry.
- Process exit keeps frame-budgeted backlog draining to avoid a UI-isolate stall, but explicitly closes any restore overlay immediately.
