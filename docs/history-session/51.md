## 用户核心目标

- 確認 Alera Git diff 僅顯示模式的自動編碼偵測是否因片段內容不完整而誤判。
- Optimize Alera diff-only encoding handling so non-UTF-8 files are decoded correctly instead of using lossy UTF-8 or being treated as binary.
- Optimize and commit Alera diff-only encoding handling for non-UTF-8 content.

## 已确认事实

- Diff full-file mode loads raw old/new blob bytes and decodes them through workspaceFileService.decodeTextBytes, which uses the workspace text encoding auto-detection path.
- Diff-only mode returns before _loadFullFileContents, so it does not use the full-file encoding detection path.
- rust/src/api/git_diff_render.rs renders libgit2 patch lines with String::from_utf8_lossy(line.content()), meaning non-UTF-8 diff content is forced through lossy UTF-8 rather than auto-detected.
- Untracked diff handling also requires String::from_utf8(bytes); non-UTF-8 untracked text is classified as binary.
- Therefore the observed diff-only encoding issue is real, but the primary cause is not incomplete-content auto-detection; auto-detection is bypassed entirely in diff-only mode.
- Diff-only previously decoded libgit2 source lines with String::from_utf8_lossy, bypassing workspace encoding detection.
- Untracked non-UTF-8 text previously used String::from_utf8 and was classified as binary on failure.
- Implemented lazy side-specific encoding detection from full old/new file content and cached the detected encoding per side.
- ASCII diff lines avoid loading full file bytes, preserving the fast path.
- Tracked Big5 diff decoding now works for unstaged, staged, and commit-backed diffs; untracked Big5 is no longer treated as binary.
- Diff-only encoding fix is committed on main.
- The commit contains only the four Rust files for encoding-aware diff rendering and regression coverage.
- Unrelated Flutter diff UI edits and untracked build/history artifacts remain outside the commit.
