## 关键设计决定

- Treat lazyOnDemand as lazy process startup, not package acquisition/download.
- Do not allow workspace/project configuration to supply arbitrary package names, URLs, versions, executables, or install commands.
- Use curated package-manager acquisition rather than arbitrary direct binary downloads for the first managed-install implementation.
- Keep acquisition behind a narrow ManagedLanguageServerInstallerPort so CodeForge runtime remains responsible only for executable resolution/startup.
- Preserve user intent: explicit executable override > PATH > managed provider install > unavailable.
- Do not automatically install or bootstrap Node.js/npm, Go, .NET SDK, or rustup at this stage.
- Use executable presence plus a lightweight real command probe instead of PATH existence alone.
- Treat .NET runtime-only installations as insufficient for csharp-ls managed installation.
- Keep prerequisite failures as Missing with recovery guidance and Check Again, rather than intrusive modal prompts.
- Keep existing explicit override > PATH > managed semantic-server install behavior.
- Used a non-fast-forward merge commit to preserve feature branch integration history.
- Did not delete or modify existing untracked build, worktree, history, or language-intelligence smoke directories.
- Re-ran Language Intelligence integration validation on main after merge.
- Distinguish prior real language-server compatibility validation from the latest status-observability test coverage.
- Use real Tree-sitter byte offsets for determinate progress; do not fabricate time-based percentages.
- Poll from Dart at 75 ms rather than adding a cross-FFI event stream, keeping parser/runtime coupling narrow.
- Use the cancellation handle for initial parse progress and retained document handle for incremental reparse progress.
- Show percentage only while Parsing; Ready remains a lifecycle state rather than a persistent 100% progress display.
- Keep internal NativeParseProgressTracker and native language registry out of the FRB public surface.
- Treat Tree-sitter document parse progress and external LSP workspace indexing as separate concepts.
- Do not claim current parser progress represents whole-project semantic readiness.
- Likely primary UX cause for 'nothing happens' is semantic navigation being default-off plus silent early return when disabled; exact runtime failures can also occur if the provider is missing/not ready.
- Treat real language-server resolution and editor open/reveal behavior as separate layers and verify both rather than relying only on fake adapter tests.
- Use real rust-analyzer for a fresh production-path validation because it is installed in the current environment and supports both same-file and cross-file definition.
