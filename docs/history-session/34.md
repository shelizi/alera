## 用户核心目标

- Investigate why Claude agent status in Alera sidebar remains working/spinning after the turn appears finished.
- Audit all Alera agent lifecycle hooks for sidebar completion reliability, not only Claude.
- Fix Alera agent lifecycle completion reliability so sidebar status does not remain spinning after agents finish.

## 已确认事实

- Claude normal success path exists: Stop is registered and normalizes to done in both Dart and Rust status paths.
- Current Claude integration omits StopFailure. Current Claude Code docs state StopFailure fires instead of Stop when a turn ends due to an API error, so these turns can remain working indefinitely.
- Claude StopFailure is missing from Rust CLAUDE_HOOK_EVENTS and CLAUDE_STATUS, and from the Dart Claude managed event list/normalizer.
- The modern terminal launch path uses the Rust host-managed hook endpoint and integration overlay; the Rust Windows Claude command is already Git-Bash-to-cmd safe, so the recent Windows quoting fix is present on the active path.
- Existing Windows Claude integration tests assert generated command strings only; no end-to-end test executes Stop through wrapper -> HTTP hook -> presence/sidebar done.
- Managed hook POST uses a 2-second timeout and suppresses all POST errors (PowerShell catch {} on Windows, || true on POSIX) with no retry. A transient failure on the final Stop can therefore leave the last state at working.
- Sidebar spinner is a reflection of underlying working state; local controller, runtime presence forwarder, and runtime delta sync all have done paths once a completion event is received.
- Shared managed HTTP hook transport (Codex/Claude/Copilot/Cursor/Antigravity/Grok/Devin) uses short loopback POST timeout and silently swallows failures without retry; final-state loss can leave sidebar working for any of these agents.
- OpenCode v1/v2 and Pi plugins use 1s fetch timeout with catch-and-drop and no retry. Amp serializes events through an in-memory queue but its POST also catch-and-drops with no retry, so a final event can still be lost.
- fx uses Herdr socket authority reports instead of the shared HTTP hook and therefore does not share the HTTP final-event loss mechanism.
- Claude is confirmed incomplete: StopFailure is absent from both registered hook events and normalization, while current Claude lifecycle includes StopFailure for API-error turn termination.
- Codex registered hooks currently stop at SessionStart/UserPromptSubmit/PreToolUse/PermissionRequest/PostToolUse/Stop. Current Codex hook docs include Interrupt and SessionEnd; Alera does not register them. A Flutter transcript watcher can synthesize Stop from task_complete/turn_aborted, but the current runtime-host-managed launch path no longer injects the Flutter-local hook environment, so this should not be treated as an authoritative mitigation without E2E verification.
- Copilot main-turn completion coverage is internally broad: Stop, SessionEnd and ErrorOccurred map to terminal states. Current GitHub Copilot docs accept Stop/SessionEnd compatibility aliases, so no main completion event gap was identified.
- Cursor registers stop and sessionEnd and maps both to done; current official event surface matches the integration. A current Cursor CLI community report says some CLI builds omit stop/afterAgentResponse/beforeSubmitPrompt, which can leave Alera working until sessionEnd on affected upstream builds.
- Antigravity registered completion coverage matches its official event surface: Stop ends the execution loop. PreToolUse omission is intentional because it requires a policy decision, not because completion is missing. A current upstream Windows report says Stop/PostToolUse may fail to fire in one IDE build, which is external to Alera.
- OpenCode v1/v2 map session.idle/session.error/status idle to SessionIdle done and busy/retry to working; lifecycle coverage looks structurally complete.
- Pi currently maps agent_end to done, but current Pi docs distinguish agent_end (one low-level run may be followed by retry/compaction/queued continuation) from agent_settled (fully settled). Alera does not consume agent_settled, so it can show done too early rather than remain spinning; agent_settled is a better authoritative completion signal.
- Amp official lifecycle surface is covered through session.start/agent.start/tool.call/tool.result/agent.end; agent.end maps to done.
- Grok has strongest completion coverage: Stop, StopFailure and SessionEnd are all registered and normalized to done.
- Devin internally has Stop and SessionEnd completion coverage. Current public Devin site confirms lifecycle hooks exist, but detailed current event reference was not independently surfaced in this audit.
- Existing Windows Claude test is command-string-level. Cross-agent final-state transport reliability needs explicit E2E coverage.
- Claude completion coverage now includes StopFailure and maps it to done/interrupted.
- Codex now registers and normalizes Interrupt and SessionEnd; Interrupt is marked interrupted.
- Pi now treats agent_end as non-terminal working and agent_settled/session_shutdown as terminal done.
- Shared managed HTTP hook scripts now retry terminal/completion events up to three times while ordinary hook events remain single-attempt.
- OpenCode v1/v2, Pi, Amp, Antigravity and Windows Copilot fallback paths now apply bounded completion delivery retries.
- Rust and Dart fallback/runtime hook paths were kept aligned so legacy/desktop-managed integrations do not retain the old single-shot completion behavior.

## 关键设计决定

- Do not modify code yet because the user asked for diagnosis/confirmation rather than explicitly requesting a fix.
- Treat missing StopFailure as a confirmed lifecycle coverage bug.
- Treat normal successful Stop remaining working as a separate reliability/delivery issue until reproduced; current lack of E2E coverage and no-retry POST path are concrete weaknesses.
- Treat shared final-event delivery retry as a cross-agent reliability fix, separate from per-agent event-schema fixes.
- Prioritize Claude StopFailure and Codex Interrupt/SessionEnd as concrete event coverage updates.
- For Pi, prefer agent_settled as final idle/done authority or otherwise account for willRetry/queued continuation semantics instead of relying solely on agent_end.
- Do not modify source in this audit turn unless the user explicitly asks to implement the fixes.
- Use bounded retries only for completion/terminal lifecycle events to avoid adding latency to ordinary tool/status traffic.
- Keep hook delivery fail-open after bounded retries so an unavailable Alera receiver never blocks the agent itself.
- Do not commit temporary Flutter dependency overrides or the temporary xterm submodule state used for isolated-worktree testing.
