## 已确认事实

- UI working 狀態本身有 spinner 與統計 count：AgentRunStateIndicator / WorkspaceAgentCompactSummary 都會在 AgentStatusState.working 顯示動畫。
- Claude event normalizer 會把 UserPromptSubmit、PreToolUse、PostToolUse 等事件映射成 working，因此不是 UI 或 normalizer 缺少 working 映射。
- 實機 isolated Claude runtime settings 位於 C:\Users\zex55\AppData\Roaming\dev.leynier\Alera\terminal_host\agent-runtime-homes\claude\home\settings.json，已安裝 Alera 的 UserPromptSubmit/PreToolUse/PostToolUse/PostToolUseFailure/PermissionRequest/Stop hooks；所以設定頁開啟與 hook 安裝本身成立。
- Windows runtime 目前為 Claude hook 產生 `cmd /d /s /c ...` 命令。Anthropic Claude Code 文件說 Windows shell-form command hooks 預設由 Git Bash 執行。
- 在同機 Git Bash 實測 `cmd /d /s /c "echo ..."` 失敗並回 exit 1；改成 `MSYS2_ARG_CONV_EXCL='*' cmd.exe /d /s /c ...` 則成功，證實 MSYS argv conversion 會破壞 /d、/s。
- Rust runtime 已對 Devin 特別使用 `MSYS2_ARG_CONV_EXCL='*' ... cmd.exe /d /s /c ...`，但一般 managed_command（包含 Claude）仍使用舊 `cmd /d /s /c`，因此 Claude 在 Windows 踩到和 Devin 相同類型的 hook bridge bug。
- Dart ClaudeRuntimeHomeService 的 Windows `_managedCommand` 也仍使用 `cmd /d /s /c`，未套用 Git Bash bridge，屬於同樣潛在缺陷。
- 根因為 Claude Code 在 Windows 以 Git Bash 執行 shell-form hooks，舊 `cmd /d /s /c` 會被 MSYS argv conversion 改寫而失敗，導致 Alera 收不到 Claude hook events。
- Rust active runtime 與 Dart Claude runtime overlay 原本都生成舊式 `cmd /d /s /c` Claude hook 命令；Devin 已有 Git Bash 安全 bridge。
- 修正後 Windows Claude hook 會使用 `MSYS2_ARG_CONV_EXCL='*'` 並明確進入 `cmd.exe /d /s /c`。
- Rust 將 Claude 與 Devin 的 Windows Git Bash bridge 抽成共用 helper，避免兩者再分岔。
- Dart runtime overlay 同步使用相同 bridge 語意。
- Codex、Grok、AGY 的 Rust runtime 目前都仍會產生 generic Windows `cmd /d /s /c ...` hook 命令，但是否出問題取決於 agent 自己用什麼 shell 啟動 hook。
- Codex 0.153.4 的 Windows hook 路徑不是 Claude/Devin 的 Git Bash/MSYS 型態；以 `cmd.exe /C` 再包一層目前 Alera 的完整 Codex hook 命令做實機 canary，結果 exit 0，沒有出現 MSYS `/d`、`/s` 改寫問題。
- Grok 1.0.13 是原生 Windows executable；本機 binary 可見 PowerShell/pwsh/GROK_SHELL 相關 Windows shell 字串，沒有證據顯示 Windows hook 經 Git Bash，因此不符合 Claude 問題成立條件。
- AGY 1.2.2 是原生 Windows executable；本機 binary 包含 `cmd /c`、`cmd.exe`、PowerShell 與 hook lifecycle 字串，且 Alera desktop AGY Windows installer 本來就直接使用 per-event `.cmd` wrapper，沒有 Git Bash/MSYS 問題跡象。
- 三者目前實際安裝的 Alera hook config 都仍可看到 generic `cmd /d /s /c ...` 命令；這本身不代表有 bug。Claude/Devin 問題的必要條件是 command 先經 Git Bash/MSYS。
- 不應把 Claude/Devin 的 `MSYS2_ARG_CONV_EXCL='*'` bridge 無差別套到所有 agents；該前綴是 POSIX shell 語法，對 native cmd/PowerShell runner 反而可能不適用。
- Claude/Devin 在 Windows 的 shell-form hook 會經 Git Bash，因此必須使用 Git Bash -> cmd bridge 並停用 MSYS argv conversion。
- Codex、Grok、AGY 沒有同樣的 Git Bash/MSYS 問題，不應全域套用 MSYS2_ARG_CONV_EXCL；Codex/Grok 維持 native cmd，AGY 維持直接 .cmd wrapper。
- 將 runner 選擇集中成明確 strategy 比散落 agent-specific 條件更安全，後續新增 agent 時也能清楚選擇執行模型。
