## 已确认事实

- Reading Diff UI、service 與 Rust 核心路徑本身大致正常；序列執行時 Reading Diff 專屬 widget cases 均通過。
- 平行執行 Flutter tests 會在 build/unit_test_assets/NativeAssetsManifest.json 產生 PathExistsException，這是 Flutter build race，不是 Reading Diff 產品問題。
- 實際使用本機 Codex 0.155.1 與 gpt-5.5 做 structured-output smoke 時，reasoning effort=max 被 API 拒絕；錯誤明確指出 gpt-5.5 僅接受 none/low/medium/high/xhigh。
- effectiveReadingDiffEffort 原本直接採用已儲存的 operation/model reasoning 值，未驗證該值是否仍受目前 model 支援，因此 stale max 會使 Reading Diff 在產生前直接失敗。
- 提交前 staged 檔案只有 lib/src/features/reading_diff/application/reading_diff_service.dart 與 test/unit/reading_diff_test.dart。
- 其他既有未提交 diff-view/editor 變更沒有被納入 commit。
- Reading Diff backend request本來已支援 file、fileAll、all scope；限制主要在 UI lifecycle/presentation。
- Reading Diff 產生後切回 Original 原本會改用 ReadingDiffText 純文字 snapshot，繞過標準 Git diff renderer，因此看起來被鎖在單欄 diff-only。
- 切換到 Full File 原本會呼叫 _load() 並清除/取消 Reading Diff state，使 Reading Diff 無法跨 content mode 保留。
- State.dispose 原本直接 ref.read(readingDiffServiceProvider)，靜態分析指出 ref 在 dispose 已不安全；測試清理時也曾實際觸發。

## 关键设计决定

- Reading Diff 產生時只接受存在於目前 model.thinkingLevels 的已設定 reasoning level；若不支援則回退 model.defaultThinkingLevel。
- 本輪修正只限 Reading Diff 路徑，不擴大修改其他 AI Assist operation，也不碰既有 unrelated working-tree 變更。
- 依使用者要求本輪不提交。
- 使用 commit message: fix(reading-diff): validate reasoning effort
- Reading Diff 本身仍使用專用 ReadingDiffView；切回 Original 時改回標準 _DiffFileList renderer，讓 unified/side-by-side 與 diff-only/full-file 設定照常生效。
- 純 presentation/content mode 切換保留 Reading Diff 結果與進行中 generation；真正來源改變、refresh、whitespace reload 仍沿用既有 invalidation/cancel 行為。
- Full File hydration 使用 preserveReadingDiff=true，不增加 reading diff generation token、不取消 active request、不清除 result/snapshot/status。
- 保留 raw original snapshot 只作正常 GitDiffResult 暫時不可用時的 fallback。
- dispose-time cancellation 改為 initState 時快取 ReadingDiffService，避免 dispose 讀 ref。
- 本輪不提交，等待使用者後續要求。
