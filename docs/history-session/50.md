## 关键设计决定

- Use a Language Intelligence abstraction rather than exposing Tree-sitter or LSP directly to the workbench.
- Separate structural parser capabilities from semantic cross-file capabilities; Tree-sitter is structural, LSP is the initial semantic provider.
- External semantic language servers are opt-in per language, default-off, and lazy-started only when needed.
- Use registry-driven string-backed language IDs/descriptors and narrow capability ports; no language-specific switches in editor/navigation/process lifecycle code.
- Keep provider process/session lifecycle in an application owner with one normal workspace-scoped provider session reused across tabs.
- Keep CodeForge behind adapters and normalize LSP UTF-16/URI results into Alera scalar SourceLocation domain types.
- Separate language detection from native parser activation because CodeForge currently configures native syntax whenever a non-empty languageId is passed.
- Initial implementation uses a compiled-in extension registry; dynamic/signed extension packages are a later phase.
- C#, Go, and PHP need Tree-sitter grammar additions; Python, Rust, TS/TSX, and JS/JSX already have native grammar support.
- Concrete external semantic-server choice per language is deferred to compatibility/smoke-test lanes rather than hard-coded into the core abstraction.
- Keep first-release language activation/provider/executable/extra-args settings local/per-device only; do not send them through runtimeSettings.update or portable configuration.
- Keep LanguageIntelligenceManager as a provider-session/lifecycle owner only; consumers depend on narrow ports such as LanguageNavigationPort.
- Keep the local MVP entirely desktop-side with no RuntimeStore or ServerActor dependency.
- If remote workspace language servers are added later, use typed narrow RPC routes and a dedicated language-server owner/handler; do not reintroduce direct RuntimeStore access in requests.rs.
- Use string-backed normalized LanguageId values and declarative LanguageCapability values.
- Use immutable extension/provider descriptors and a registry that validates provider capability/declaration consistency before registration.
- Keep provider instantiation lazy through a factory registration; Phase A does not introduce a giant provider interface.
- Keep LanguageIntelligenceSettings sparse/default-off and unconnected to RuntimeStore/runtimeSettings.update.
- Keep language_intelligence domain/application Riverpod-free with an architecture guard.
- Continue automatically into Phase B after the green Phase A commit.
